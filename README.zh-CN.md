# 一眼懂文案

[English](README.md)

把界面、通知、帮助和产品介绍改成用户一眼看懂的日常说法。

适用于菜单、按钮、表单、错误提示、空状态、引导、通知、帮助说明、产品介绍和客服回复。保留功能与事实，不确定的含义先问，默认输出“原文案 → 新文案”对照表。

## 核心规则

- 用具体、熟悉的词，让用户知道点击后会发生什么。
- 保留金额、时间、费用、权限、条件和操作后果。
- 同一概念名称一致，不同动作保持区分。
- 字数按语言和场景调整。
- 改文案时保留菜单位置、顺序、分组与功能。

| 已知场景 | 原文案 | 新文案 |
| --- | --- | --- |
| 菜单显示发票列表 | 发票管理中心 | 发票 |
| 按钮只保存草稿，不送审 | 提交 | 保存草稿 |
| 发票列表已加载，确实没有发票 | 暂无数据 | 还没有发票 |

## 语言与字数

技能说明使用英文，实际输出跟随你指定的语言或产品现有语言。中文后台仍输出中文。

中文界面短文案默认：名称 **2–4 字**，单句说明 **不超过 20 字**。错误提示、通知、帮助说明等按场景保留必要信息。英文标签通常使用 1–3 个常用词。明确的字数要求优先；限制与关键含义冲突时，先提问。

## 安装到 Codex

将仓库克隆到个人技能目录：

```sh
git clone https://github.com/dongyu-will/plain-language-copy.git "${CODEX_HOME:-$HOME/.codex}/skills/plain-language-copy"
```

目录已存在时，先检查现有文件，再更新，避免覆盖自己的改动。技能尚未出现在列表中时，开始一个新对话。

这是纯指令技能，无需 API 密钥或额外运行依赖。

## 使用

```text
$plain-language-copy
重写下面的文案，让第一次使用的人一眼看懂。
功能和事实不改，输出“原文案 → 新文案”对照表。
功能含义不确定时先问我：
[粘贴文案及必要的功能说明]
```

也可以提供允许读取的页面或文件位置。默认在对话中交付建议；希望直接应用到项目时，在请求中说明。

## 贡献

修改规则时，请附上真实的原文例子、已知功能和预期结果，并说明现有指令哪里不足。通用规则留在入口文件，场景细节放在参考文件。

## 灵感与致谢

灵感来自[向阳乔木（@vista8）于 2026 年 10 月 8 日发布的 X 帖子](https://x.com/vista8/status/2107887033947660597)，讨论如何让 AI 开发的后台菜单和功能说明更易懂。本项目将这个想法扩展成覆盖更多产品与服务场景的可复用技能。

写作原则参考 Steve Krug 的《Don't Make Me Think》、Robin Williams 的《写给大家看的设计书》，以及精炼、具体、克制的产品表达。
